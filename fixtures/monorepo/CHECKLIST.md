# Production checklist

The items of the [Pyahu Initializer guides](https://initializer.pyahu.io/guides/) that apply to this project.
Mark each one pass, fail or not applicable and write down the reason for every exception. The link on an item
explains why it matters. Much of the generated configuration already passes; the rest is yours.

## Part 1: Foundations

### [Build and code quality](https://initializer.pyahu.io/guides/build-quality/)

- [ ] **BLD-01** Gradle wrapper committed with distributionSha256Sum and CI always runs ./gradlew. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-wrapper))
- [ ] **BLD-02** Java toolchain set to 25 in the build and CI builds inside the pinned JDK image. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-wrapper))
- [ ] **BLD-03** Every library and plugin version in gradle/libs.versions.toml; no version typed in a build file. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-version-catalog))
- [ ] **BLD-04** Repositories declared only in settings.gradle.kts with repositoriesMode FAIL_ON_PROJECT_REPOS. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-version-catalog))
- [ ] **BLD-05** BOMs imported with platform() in every configuration that needs them; no io.spring.dependency-management plugin. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-boms))

- [ ] **BLD-07** NullAway as an error with OnlyNullMarked and JSpecifyMode; RequireExplicitNullMarking fails a package without a package-info.java with @NullMarked. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-nullaway))
- [ ] **BLD-08** Spotless with a pinned palantir-java-format; spotlessCheck runs as part of check. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-format))
- [ ] **BLD-09** build depends on cyclonedxBom and writes the SBOM to a fixed path. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-sbom))

- [ ] **BLD-12** PMD runs in check on handwritten code with a short ruleset for complexity, size and swallowed errors. ([step](https://initializer.pyahu.io/guides/build-quality/#bld-complexity))

### [Testing a Spring Boot service](https://initializer.pyahu.io/guides/testing/)

- [ ] **TEST-01** Domain classes depend on no Spring type and their tests start no Spring context. ([step](https://initializer.pyahu.io/guides/testing/#test-domain))
- [ ] **TEST-02** Each adapter has a slice test: @WebMvcTest for controllers, @DataJdbcTest for repositories, @RestClientTest for HTTP clients. ([step](https://initializer.pyahu.io/guides/testing/#test-slices))
- [ ] **TEST-03** An ApplicationModules.verify() test and an ArchUnit class with the jMolecules rule for the chosen style run in the normal build. ([step](https://initializer.pyahu.io/guides/testing/#test-architecture))
- [ ] **TEST-04** Database tests run against Testcontainers PostgreSQL of the production major version through @ServiceConnection, never a database that runs in memory. ([step](https://initializer.pyahu.io/guides/testing/#test-real-database))
- [ ] **TEST-05** The real migrations run in tests, so a changeset that does not apply fails the build. ([step](https://initializer.pyahu.io/guides/testing/#test-real-database))
- [ ] **TEST-06** Outbound clients are built from Boot's RestClient.Builder and tested with @RestClientTest, error responses included. ([step](https://initializer.pyahu.io/guides/testing/#test-outbound-http))

- [ ] **TEST-08** A suite starts the built image with a read-only root filesystem as a user other than root and asserts that /readyz answers 200. ([step](https://initializer.pyahu.io/guides/testing/#test-image))
- [ ] **TEST-09** CI runners have Docker for the Testcontainers and image tests. ([step](https://initializer.pyahu.io/guides/testing/#test-real-database))
- [ ] **TEST-10** Tests that start the application or a container carry @Tag("integration") and run in their own task after the fast tests. ([step](https://initializer.pyahu.io/guides/testing/#test-strength))

### [The database in production](https://initializer.pyahu.io/guides/database/)

- [ ] **DB-01** Connection budget computed: every pool times HPA maximum, surge and draining pods, plus migrations and admin, fits the user connections of each database server. ([step](https://initializer.pyahu.io/guides/database/#db-connection-budget))
- [ ] **DB-02** Fixed pool: maximum-pool-size equals minimum-idle, 10 or less unless measured otherwise. ([step](https://initializer.pyahu.io/guides/database/#db-connection-budget))
- [ ] **DB-03** connection-timeout between 2000 and 5000 ms, max-lifetime below every connection age cap, keepalive-time below network idle timeouts, leak-detection-threshold set. ([step](https://initializer.pyahu.io/guides/database/#db-pool-timeouts))
- [ ] **DB-04** spring.transaction.default-timeout and spring.jdbc.template.query-timeout set. ([step](https://initializer.pyahu.io/guides/database/#db-query-timeouts))
- [ ] **DB-05** Runtime role has statement_timeout and idle_in_transaction_session_timeout. ([step](https://initializer.pyahu.io/guides/database/#db-query-timeouts))
- [ ] **DB-06** Separate migration and runtime users; the runtime user cannot change the schema or write Liquibase history/lock tables, and can read history for readiness. ([step](https://initializer.pyahu.io/guides/database/#db-roles))
- [ ] **DB-07** Migrations run in a Job before the rollout; the application sets spring.liquibase.enabled to false. ([step](https://initializer.pyahu.io/guides/database/#db-migrations))
- [ ] **DB-08** Every schema change reviewed as expand and contract; no rename or drop in the same release as the code change. ([step](https://initializer.pyahu.io/guides/database/#db-expand-contract))
- [ ] **DB-09** Transactional changesets start with SET LOCAL lock_timeout; changesets that ran are never edited. ([step](https://initializer.pyahu.io/guides/database/#db-expand-contract))
- [ ] **DB-10** Integration tests run the real changelog on Testcontainers with the production PostgreSQL major version. ([step](https://initializer.pyahu.io/guides/database/#db-testing))
- [ ] **DB-11** Alerts on hikaricp.connections.pending and hikaricp.connections.timeout. ([step](https://initializer.pyahu.io/guides/database/#db-pool-metrics))
- [ ] **DB-12** Point in time restore rehearsed in the last quarter. ([step](https://initializer.pyahu.io/guides/database/#db-pool-metrics))
- [ ] **DB-13** Namespace, ServiceAccount, ConfigMaps, NetworkPolicies, database roles and Secrets exist before the migration Job; it completes before the rollout and a failed Job stops the release. ([step](https://initializer.pyahu.io/guides/database/#db-migration-job))
- [ ] **DB-14** The migration Job has a versioned name (or is recreated by its hook), a low backoffLimit, an activeDeadlineSeconds and a ttlSecondsAfterFinished. ([step](https://initializer.pyahu.io/guides/database/#db-migration-job))

- [ ] **HTTP-13** Circuit breaker or rate limiter only with a written reason, using resilience4j-spring-boot4. ([step](https://initializer.pyahu.io/guides/http-clients/#http-bulkhead))

### [Virtual threads and concurrency](https://initializer.pyahu.io/guides/virtual-threads/)

- [ ] **VT-01** spring.threads.virtual.enabled is true only for I/O bound services; the decision is recorded. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-enable))
- [ ] **VT-02** HikariCP maximum-pool-size comes from the database connection budget; connection-timeout is 5 s or less. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-resource-limits))
- [ ] **VT-03** Each downstream client shares a concurrency limit with explicit rejection; any waiting queue is bounded with an admission deadline, and outbound calls have connect and read timeouts. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-downstream-limits))
- [ ] **VT-04** CPU heavy work runs on a platform pool sized to the cores with a bounded queue and explicit rejection. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-cpu-work))
- [ ] **VT-05** Pod CPU request of at least 1; either -XX:ActiveProcessorCount of at least 2 with no CPU limit or a CPU limit of at least 2. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-cpu-work))
- [ ] **VT-06** No custom executor bean silently replaces the virtual thread @Async executor; spring.main.keep-alive is true for apps without a web server. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-executors))
- [ ] **VT-07** MDC, security and trace context are propagated across async boundaries; no business logic relies on ThreadLocal caching. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-context))
- [ ] **VT-08** Fan out uses a long lived, context wrapped executor and cancels the tasks that miss the deadline. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-fan-out))
- [ ] **VT-09** A JFR pinning check runs once under load; dashboards show pool pending connections and GC. ([step](https://initializer.pyahu.io/guides/virtual-threads/#vt-pinning))
