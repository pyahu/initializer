# monorepo

Monorepo fixture

A platform of verticals in one Gradle build, generated by the [Pyahu Initializer](https://initializer.pyahu.io/) on
baseline v0.1-b3: Java 25 and Spring Boot 4.2.0. It follows the
[monorepo guide](https://initializer.pyahu.io/guides/monorepo/): each vertical owns its code, contract, database, image and
deployment, and the build keeps them apart. `AGENTS.md` says how it is organised; `CHECKLIST.md` lists what to
check before production. The [release notes](https://initializer.pyahu.io/releases/#v0-1-b3) say how to move it to a newer baseline.

| Vertical | Architecture | Database | Local port |
| -------- | ------------ | -------- | ---------- |
| [`billing`](verticals/billing/) | DDD layered | none | 8110 |
| [`orders`](verticals/orders/) | Hexagonal | PostgreSQL | 8120 |

## Run it

You need Java 25 and Docker.

```sh
./gradlew build :build-logic:check   # every project, every gate, the conventions' tests
./gradlew :<vertical>:bootRun        # one vertical, with its local dependencies in Docker
docker compose up -d                 # the dependencies of every vertical
```

Telemetry goes to Grafana on http://localhost:3000 (admin/admin). The mock identity provider on
http://localhost:8090/default signs in any user name; in each environment set `OIDC_ISSUER_URI` and
`OIDC_AUDIENCE` (security guide).

## Ship it

Each vertical has its own image, built from the repository root, and its own Kustomize tree in
`verticals/<vertical>/service/deploy/`:

```sh
docker build -f verticals/<vertical>/service/Dockerfile -t <vertical> .
```

CI (`.github/workflows/ci.yml`) builds and tests every project once, checks every contract against the base of the
change, then builds, scans and starts each vertical's image. Its `gate` job is the one check to require on `main`.
