The guides are the product. They hold current, correct, production-tested practice, and every claim says how it
was proven. This page is the short version; the full rules, which `guidekit check` enforces, are in
[CONTRIBUTING.md](https://github.com/pyahu/initializer/blob/main/CONTRIBUTING.md).

## Writing

- English. Short sentences, tables and code before prose.
- If a paragraph does not change a decision or prevent a failure, cut it.
- Teach, do not just prescribe: every decision is a problem, a solution, its use cases, and its trade-offs.
- One canonical place per decision; other pages link to it.
- Primary sources only. Versions stated. Anything not proven carries a `not exercised` record.
- No em or en dashes. Write ranges as "2 to 4".

## A guide page

1. **Status**: state, baseline, verification, coverage, sources, and the questions the guide answers.
2. **Decision summary**: the failure, the choices, when they are wrong, the core diagram. About 150 to 250 words.
3. **Decision cards**, one per decision, each with a stable anchor and five parts in this order: Problem,
   Solution, Use cases, Trade-offs, Evidence.
4. **Recipes**: an excerpt from a tested fixture file, a link to the complete file, the expected result, and what
   to do when it fails.
5. **Checklist** and **References**, rendered from the data files.

A reader who only needs the answer stops at the summary. A reviewer stops at the cards.

## Evidence

Each record states one claim and carries one badge:

| Badge | Means |
| ----- | ----- |
| `compiled` | Code compiled against the stated versions |
| `reproduced` | Behaviour reproduced by a named test in CI |
| `measured` | Numbers with the environment and protocol they came from |
| `cluster-run` | Applied and exercised on a real cluster |
| `not exercised` | Reasoned from documentation only, shown prominently |

A card lists every record; there is no single badge per card. The fixture workflow re-runs every named test on
each change, so a claim that stops being true turns CI red.

## States

- **Draft**: decided, being proven by a fixture.
- **Released**: applies to a released template, with its evidence.
- **Explanatory**: a comparison that is never generated.

## Checklist items

Each item has a stable ID such as `JVM-03` and one type: generated configuration, verified behaviour,
deployment prerequisite, or recurring operator task. An item is "enforced" only when a test fails if the behaviour
breaks.
