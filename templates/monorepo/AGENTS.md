# Working in this repository

[[description]]

A platform of verticals in one Gradle build, generated by the [Pyahu Initializer](https://initializer.pyahu.io/) on
baseline [[baseline]]: Java [[javaFeature]] and Spring Boot [[springBoot]]. Each vertical is a service that owns its code, contract,
database, image and deployment. The build keeps them apart; this page says how. Each vertical's own `AGENTS.md`
says what is particular to it: read it before you change that vertical.

## Where things are

| Path | What |
| ---- | ---- |
[[#verticals]]
| `verticals/[[name]]/` | The [[name]] vertical: [[architectureTitle]][[#postgres]], with PostgreSQL[[/postgres]], on port [[port]] locally. |
[[/verticals]]
| `verticals/<vertical>/service/` | Its Spring Boot service: code, image, manifests in `deploy/`, local dependencies in `compose.yaml`. |
| `verticals/<vertical>/api/` | Its contract, `src/main/openapi/<vertical>.yaml`, and the code generated from it once. |
| `libs/<name>/` | Code that several verticals reuse on purpose. Empty until there is some. |
| `build-logic/` | The convention plugins every project applies, and their tests. |
| `gradle/libs.versions.toml` | Every version of the build, and the only place for one. |
| `platform.compose.yaml` | What every vertical needs on the laptop: Grafana LGTM[[#oidc]] and the mock identity provider[[/oidc]]. |
| `compose.yaml` | Every vertical's local dependencies at once. |
| `.github/workflows/` | `ci.yml` for the whole platform, `vertical.yml` for each vertical's image. |
| `docs/adr/` | Decisions, starting with why the verticals share a repository. |

## Rules the build enforces

A change that breaks one of these fails `./gradlew build`. Fix the code. Do not lower a limit, switch a check off
or leave code out of one to get to green.

- **A vertical never uses another vertical's code.** Gradle stops when a service depends on another service's
  project, and each vertical's `ArchitectureTest` fails on a class that reaches into another vertical. Use its
  `api` project, the contract it offers, or a library.
- **A contract is only broken on purpose.** CI compares every `api` contract with the base of the change and fails
  on a breaking one. Remove something in three pull requests: add the new, move every consumer, then remove the
  old with the `breaking-change` label.
- **Every project applies one convention plugin** from `build-logic`: `platform.service`, `platform.api` or
  `platform.library`. A build file adds only what makes its project different. No `allprojects`,
  `subprojects` or `afterEvaluate`.
- **Versions live in the catalog.** No build file or convention plugin writes a version.
- **Each vertical keeps its own architecture**, the quality gates and its quality report in
  `verticals/<vertical>/service/build/reports/pyahu/quality.json`: read it first when the build fails.

## Commands

```sh
./gradlew build :build-logic:check     # every project and the conventions' own tests, as CI runs them
./gradlew :<vertical>:build            # one vertical, with its contract
./gradlew :<vertical>:bootRun          # one vertical, with its compose.yaml started for it
docker compose up -d                   # every vertical's dependencies, to run several
./gradlew spotlessApply                # format
```

## Adding a vertical

Copy the folder of the vertical closest to what you need into `verticals/<name>/`, then rename its package and its
names. The build and CI find it by its folder. By hand: a line in `compose.yaml`, one in `.github/CODEOWNERS`
and the next free local ports in its `build.gradle.kts`.

## Upgrading to a newer baseline

The [release notes]([[releaseNotes]]) list every step after baseline [[baseline]], oldest first. Run a step's
**Needed when** command from the repository root and apply the step only when it exits 0, then run its **Check**.

## Leave these to a person

`build-logic/`, `gradle/`, `gradlew`, `renovate.json`, `config/pmd/`, `.github/`, `platform.compose.yaml`,
`CHECKLIST.md` and the `AGENTS.md` files hold the rules a change is judged by. A change to one of them is its own
pull request, with its reason.
